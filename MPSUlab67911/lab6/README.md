# Лабораторная работа №6 для ПИН/ПМ

Проект объединяет три части из [курса APS](https://github.com/MPSU/APS/tree/russian_version/Labs):

1. [7. Тракт данных](https://github.com/MPSU/APS/tree/russian_version/Labs/07.%20Datapath).
2. [9. Интеграция LSU](https://github.com/MPSU/APS/tree/russian_version/Labs/09.%20LSU%20Integration).
3. [11. Интеграция прерываний](https://github.com/MPSU/APS/tree/russian_version/Labs/11.%20Interrupt%20integration).

Индивидуальная программа — **вариант 21** из ЛР4: сложить четыре тетрады младших 16 бит числа. Для входа `0x1230` результат в `x10` равен **6**. Дополнительно результат записывается по адресу `0` памяти данных.

## Запуск в Vivado на другом компьютере

После скачивания репозитория открой Vivado и закрой предыдущий проект. В **Tcl Console** перейди в каталог `MPSUlab67911/lab6` внутри скачанной папки и выполни:

```tcl
set lab6_test lab11
source scripts/create_project.tcl
launch_simulation
run all
```

Скрипт сам найдёт исходники относительно своего расположения и создаст проект `.vivado/lab11/lab6_lab11.xpr`. Используется та же FPGA, что в заготовке: `xc7a100tcsg324-1`. Абсолютных путей к исходному компьютеру в рабочей конфигурации нет.

По умолчанию запускается **оригинальный `lab_11_tb_processor_system` из MPSU/APS**, файл `tests/upstream/lab_11.tb_processor_system.sv`. Он сохранён без изменений. Память инициализируется оригинальным `program.mem` из ЛР11.

В готовом `lab6.xpr` также выбран `lab_11_tb_processor_system`. Симуляция открывается на времени `0 ns`; нажми **Run All** один раз. Ожидаемое завершение оригинального теста:

```text
The test is over
See the internal signals of the module on the waveform
```

Этот тест курса предлагает самостоятельно проверить значения по временной диаграмме и не печатает `PASS tb_lab6: 126 checks`. Для повторного выполнения используй **Restart**, затем **Run All**. Запускать `Run All` после `$finish` без перезапуска не нужно: в оригинальных тестах остаётся сторожевой таймер.

Варианты запуска выбираются **перед** созданием проекта:

```tcl
set lab6_test individual
source scripts/create_project.tcl
launch_simulation
run all
```

| `lab6_test` | Что проверяется |
| --- | --- |
| `lab11` | По умолчанию: оригинальный тест ЛР11 и её программа |
| `lab07` | Оригинальный тест ЛР7 и её программа |
| `lab09` | Тот же оригинальный тест ЛР7, как предписывает задание ЛР9 |
| `selftest` | Дополнительный авторский тест: 126 проверок результата |
| `individual` | Дополнительный тест варианта 21: `x10 = RAM[0] = 6` |
| `memory`, `lsu`, `csr`, `irq` | Отдельные блоки, тесты из курса |
| `board` | Проект для Nexys A7-100T с индивидуальной программой |

Для смены варианта закрой текущую симуляцию и проект, затем заново выполни команды создания с `set lab6_test lab07`, `lab09` или `lab11`. Для первого запуска удобнее создать чистый проект скриптом.

Из командной строки, где доступна команда `vivado`, можно запустить оригинальные тесты всех трёх частей работы:

```text
vivado -mode batch -source scripts/run_vivado.tcl -tclargs all
```

Или только один: замени `all` на `lab07`, `lab09` или `lab11`. Оригинальные тесты остаются без изменений и завершаются сообщением о просмотре временной диаграммы. Для дополнительной автоматической проверки результатов доступен отдельный режим `selftest`.

## Что реализовано

Верхний модуль `processor_system(clk_i, rst_i)` имеет активный высокий синхронный сброс. Ядро называется `core`, память инструкций — `instr_mem`, память данных — `data_mem`, как требуется тестами курса.

```text
instr_mem -> processor_core <-> LSU <-> data_mem
                  |                byte enable, ready
                  +-- CSR
                  +-- interrupt_controller
```

Ядро соединяет декодер, АЛУ и регистровый файл. Константы I/S/B/J расширяются знаком, U дополняется 12 нулями справа, Z расширяется нулями. Реализованы условные переходы, `jal`, `jalr` с очисткой младшего бита адреса и выбор результата для записи в регистры.

LSU поддерживает `lb/lbu/lh/lhu/lw` и `sb/sh/sw`, выбирает байтовые линии и удерживает процессор на время доступа к синхронной памяти. Сигнал `ready` приходит от памяти; отдельного регистра остановки в верхнем модуле нет.

Подсистема прерываний использует учебную схему курса: маска `mie[16]`, вектор `mtvec`, адрес возврата `mepc`, причина `mcause`, временный регистр `mscratch`. Причина внешнего прерывания — `0x80000010`; нелегальная инструкция, включая `ecall` в этой учебной реализации, вызывает исключение с кодом `2`. Команда `mret` возвращает управление через `mepc`.

Запись в регистры и CSR запрещена во время сброса, остановки и перехвата инструкции. Прерванная CSR-инструкция не меняет CSR заранее и корректно выполняется после возврата. Запись в `x0` блокируется. Последовательная логика контроллера прерываний использует неблокирующие присваивания.

По умолчанию `ENABLE_TRAPS=1`: это итоговая версия после части 11. Для проверки программы частей 7/9 используется `ENABLE_TRAPS=0`, поскольку та программа специально содержит неподдерживаемые `mul` и нулевую инструкцию. Нелегальные инструкции в этом режиме пропускаются без записи результата. В режимах `lab07` и `lab09` скрипт задаёт флаг компиляции дизайна `APS_DATAPATH_CHECKPOINT`; исходный тестбенч курса при этом не меняется.

## Программы и ожидаемые результаты

| Файл | Результат |
| --- | --- |
| `programs/lab07.mem` | `PC=0x64`, `x10=x11=0xFADEBABE`, `x12=0xFFFFBABE`, `x13=0xFFFFFFBE` |
| `programs/lab11.mem` | После исключения и одного IRQ: `PC=0x34`, `RAM[0]=4`, `x2=0x1F0`, `mscratch=0xF0`, `mcause=0x80000010` |
| `programs/individual.mem` | Для `sw_i=0x1230`: `x10=6`, `RAM[0]=6`, финальный `PC=0x34` |

`programs/individual.S` содержит читаемый исходник индивидуальной программы. В соответствии с условием для RISC-V вход `sw_i` задаётся константой в программе. Вариант 21 взят из [списка индивидуальных заданий](https://github.com/MPSU/APS/tree/russian_version/Labs/04.%20Primitive%20programmable%20device/%D0%98%D0%BD%D0%B4%D0%B8%D0%B2%D0%B8%D0%B4%D1%83%D0%B0%D0%BB%D1%8C%D0%BD%D0%BE%D0%B5%20%D0%B7%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5).

Для изменения входа поправь первые `lui/addi` и пересобери образ:

```text
python scripts/assemble.py programs/individual.S programs/individual.mem
```

Сборщик поддерживает команды, использованные в приложенных программах, метки и `.org`; это небольшой инструмент для этих примеров, без псевдоинструкций и линкера. Его кодировка сверена со всеми 38 инструкциями официального образа ЛР11. При изменении индивидуального примера обнови ожидаемый результат в `tests/tb_individual.sv`.

## Проверки и просмотр сигналов

Оригинальные тестбенчи для трёх частей находятся в `tests/upstream`: `lab_07.tb_processor_system.sv` используется для частей 7 и 9, `lab_11.tb_processor_system.sv` — для части 11. Для итоговой части основные сигналы находятся внутри `lab_11_tb_processor_system/DUT`. Добавь на диаграмму `core/pc`, `instr`, `stall`, `irq_req`, `irq_ret`, `core/mepc`, `core/mtvec`, `core/register_file/rf_mem` и `data_mem/ram` и сравни с таблицей ожидаемых результатов выше.

Оригинальные тесты локально запускаются через Python 3 и Verilator:

```text
python3 scripts/run_tests.py --test lab07 --test lab09 --test lab11
```

Дополнительные авторские проверки можно выполнить отдельно:

```text
python3 scripts/run_tests.py --waves
```

Проверяются исходные примеры курса, все пять видов загрузки, три вида сохранения, знаковое расширение, сохранность невыбранных байтов, зависимости после загрузки, арифметика, шесть условных переходов, отрицательные смещения, `jal/jalr`, CSR, исключение и прерывание. Вариант 21 проверяется на `0`, `0x1230`, `0xFFFF`, `0x8000`, `0xFEDC`, `0xDEADBEEF`.

Логи сохраняются в `.build/*.log`, результат — `.build/test_results.txt`, временная диаграмма дополнительного общего теста — `.build/integration_run/lab6.vcd`.

В Vivado используются сами оригинальные файлы из `tests/upstream`, без генерации изменённых копий. Тесты частей 7/9 и 11 также компилируются в Verilator без правок. Только для дополнительных проверок отдельных блоков в Verilator создаются копии с адаптациями совместимости: время подачи входов IRQ, начальная интерактивная пауза CSR, неявный тактовый сигнал в одном CSR-assertion, выбор допустимых размеров LSU без SMT-солвера и проверка размеров массива вместо чтения `X` за границами.

## Проверка на плате

Выполни `set lab6_test board`, затем создай проект тем же скриптом. В `board` включены обёртка и ограничения из ЛР7 для Nexys A7-100T. Обёртка адаптирована для версий Vivado без поддержки параметров типа; назначение портов сохранено. Кнопка BTND продвигает процессор по тактам, CPU_RESET выполняет сброс при одновременном нажатии кнопки тактирования. Индикаторы показывают PC и тип инструкции. После выполнения индивидуальной программы PC остаётся равен `0x34`.

Синтез, реализацию и программирование платы нужно выполнить в Vivado на компьютере с платой. Локально выполнены симуляции оригинальных тестов частей 7/9 и 11 в Verilator и проверка компиляции обёртки. Дополнительный авторский `tb_lab6` прошёл все 126 проверок в XSim из Vivado 2023.1 на Windows. Оригинальные тесты курса следует запустить в XSim описанными выше командами. Сама плата пока не проверена.
